# Emulate worktree isolation and manual-only invocation where a harness lacks them

Status: accepted (decided by the user on 2026-11-06). Amends [ADR 0012](0012-portable-cores-as-claude-and-reduced-capability.md).

ADR 0012 kept refusing `isolation: worktree` everywhere but Claude Code, and agnthub refused Copilot CLI agents with `disable-model-invocation: true` (or the retired `infer: false`) on every other harness. Six listed repositories installed on one harness only because of these two fields and of `WebFetch(*)`. The native equivalents were checked against first-party docs and the CLIs pinned in the e2e images ([harness-agent-formats.md](../research/harness-agent-formats.md#manual-only-invocation-and-worktree-isolation-verified-2026-11-06)): only Claude Code isolates one agent in its own worktree from its definition, and only Copilot CLI (`disable-model-invocation: true`) and OpenCode (`mode: primary`) keep an agent out of the model's reach.

**A whole-tool wildcard is the tool.** Claude Code reads `Tool(*)` as `Tool` ([permissions](https://code.claude.com/docs/en/permissions#match-all-uses-of-a-tool): "`Bash(*)` is equivalent to `Bash`"; Claude Code 2.1.309 drops a rule content of exactly `*`). So `WebFetch(*)`, `Bash(*)` or `Read(*)` converts as the plain tool. Only exactly `*` qualifies: `Bash(git *)` keeps its shell-scope handling and `WebFetch(domain:x)` stays refused.

**Manual-only invocation is a preference, not a permission.** It decides when the agent runs, never what it may do. Copilot CLI writes `disable-model-invocation: true`, and OpenCode writes the agent as a primary agent (`mode: primary`), which the user selects and OpenCode's subagent tool refuses. Every other harness installs it with its tools unchanged, with the description starting "Use only when the user explicitly asks for this agent." (delegating models choose agents by their description), and a `! reduced:` line (`manual-only invocation`): "<harness> may delegate to it automatically; the description asks it not to". No opt-in is needed.

**Worktree isolation is containment, emulated by instruction.** Claude Code keeps `isolation: worktree`. On every other harness, an agent that can run any shell command installs by default with a firm instruction at the top of its instructions to create a dedicated git worktree, work and commit only there, never touch the user's working tree, and report the worktree path and branch; the plan, `--json`, the assessment and the registry show a `! reduced:` line (`isolation`): "<harness> can't isolate it; the agent is instructed to work only in a git worktree". An agent that edits files without such a shell (none, or one limited to some commands, or Cursor's `readonly`, which blocks the shell) cannot create a worktree, so it stays refused on that harness, with that reason. An agent that neither edits nor runs commands changes nothing, so isolation is moot: it installs with no instruction and no note. Other `isolation` values (Claude Code's undocumented `remote`) stay refused.

Consequences: this is the one place where a restriction is carried in prose rather than enforced. The user chose it over an opt-in flag; the reduction line keeps it visible wherever the agent is listed or installed, and the agent can still edit the user's working tree if it ignores the instruction. Hooks with real events, Codex agents that withhold edits and Cursor agents that withhold reads stay refused as ADR 0012 decided.
