# Convert native agents across harnesses through a shared semantics model

Most published agents exist only as one harness's native file (typically `.claude/agents/*.md`). Converting only from the portable core left them installable on that one harness, even when every other harness can express what they declare. Conversion now goes through one harness-neutral **Semantics** model: identity, description, instructions, a model hint, a tool policy over capabilities (read, search, edit, shell, web fetch, web search, delegation, todo list, skills, plus MCP and unknown tool names), turn limit, background execution, harmless omissions and unsupported behaviors. Every adapter parses its native format into Semantics and renders Semantics into its native format.

For a target harness without an authored Variant, sources are tried in a fixed order: the portable core, then every other authored Variant, Claude Code first and the rest in display order. The first source the target can represent wins; otherwise the first refusal is reported. An authored Variant for the target is still installed as is, and an invalid one still never falls back ([ADR 0002](0002-agent-variants-and-conservative-conversion.md)).

Mapping keeps ADR 0002's conservative rule. Identity, description and instructions always carry. Cosmetic fields and session helpers that grant nothing elsewhere (for example Claude's `color` or `SendMessage`) are omitted with a note. Model strings are never carried: the converted agent uses the target's default model and the plan says so. Tool allowlists translate per capability; an allowlist granting a capability the target lacks (delegation for Gemini, web search for Copilot CLI) is refused. Excluding a boundary capability (reads, searches, edits, shell) the target cannot withhold is refused; network tools, delegation and inherited MCP servers that a target cannot withhold are noted, because they never change files themselves. Behavioral and safety fields with no target equivalent (hooks, permission modes, scoped MCP servers, isolation, memory, approval prompts, scoped tool rules) are refused; turn limits and background execution map where the target has them. Every generated file is validated with the target's own Variant validator before it is offered.

Generated artifacts record converter `<harness>/v3`. Each converter version renders what its predecessors converted byte for byte (v2 added native Variant sources, v3 MCP tool references), so locks written by v1 or v2 restore unchanged; a regenerated digest mismatch is reported as a converter change rather than substituted. The registry's assessment version is bumped so every indexed repository is re-assessed on its next refresh.

MCP tool references (`mcp__<server>__<tool>`, or a whole server) translate to each target's own MCP tool name where the target can list them per agent: OpenCode `<server>_<tool>` permissions plus its Code Mode `execute` action, Copilot CLI's exposed `<server>-<tool>` names, Gemini CLI `mcp_<server>_<tool>`, Claude Code `mcp__<server>__<tool>`. omp, Codex and non-read-only Cursor agents already keep every session MCP tool whatever their tool list says, the residual surface every converted allowlist on them carries, so an agent naming MCP tools converts there with that surface noted rather than refused. A name the target cannot address (a whole server for Copilot CLI, a Gemini or Copilot name beyond its length limit, an OpenCode permission that would also match a built-in action, MCP tools on a read-only Cursor agent) is refused. Every plan names the MCP servers the agent needs; agnthub never installs or edits MCP server configuration. Claude Code plugin servers (`plugin_<plugin>_<server>`) are named by their server name, and Claude Code's built-in `ide` connection is omitted with a note.

Consequences: native-only agents become installable wherever their declared semantics fit, with the omissions and residual surfaces stated in the plan. The capability model is the unit of translation (an allowlist naming Edit but not Write grants edits as a whole, noted), so per-tool or per-command nuance beyond it still requires an authored Variant. Harness tool vocabularies are pinned to the CLI versions in [harness agent formats](../research/harness-agent-formats.md) and need revisiting when those harnesses change.
