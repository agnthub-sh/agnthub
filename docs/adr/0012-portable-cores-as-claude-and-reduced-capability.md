# Read portable cores as Claude Code agents and install reduced capability visibly

Status: accepted (decided by the user on 2026-11-05). Amends [ADR 0002](0002-agent-variants-and-conservative-conversion.md). Amended by [ADR 0014](0014-emulate-worktree-isolation-and-manual-only-invocation.md) (worktree isolation and manual-only invocation) and [ADR 0019](0019-read-agent-md-cores-as-copilot-agents.md) (`<id>.agent.md` cores are read as Copilot CLI agents).

ADR 0002 limited the portable core to `name`, `description` and the body, with harmless metadata omitted: any other key refused conversion for every harness. A registry census (2026-11-05, 144,705 agents) found that 96% of portable cores are `agents/*.md` files written for Claude Code (`model: sonnet`, `tools: Read, Grep`, `color`…), and that about 14,000 of them were hidden because of those keys. It also found agents refused only because a harness cannot grant a capability they use, while the conversion would never have widened what they may do.

**Portable cores are read as Claude Code agents.** The extra frontmatter fields of a portable core (an `agents/*.md` file or any other portable definition) have their Claude Code meaning, parsed by the same semantics parser as a `.claude/agents/` file ([ADR 0009](0009-cross-harness-conversion-through-shared-semantics.md)): `model` is carried to Claude Code and noted elsewhere, `color` is dropped, `tools`/`disallowedTools` become the tool policy, keys Claude Code ignores are omitted with a note, values that restrict nothing (`permissionMode: default`, empty lists) are omitted with a note, and keys Claude Code ignores but that read as restrictions (`permission`, `allowed-paths`, delegation lists such as `agents`…) still refuse. Behaviors with no cross-harness equivalent (real hook events, `isolation: worktree`, agent-scoped MCP servers outside Gemini CLI) refuse as for any Claude Code Variant.

**Reduced capability installs with a prominent note.** When a target cannot grant a capability the agent uses, and the only faithful alternative is to withhold it (which never widens what the agent may do), the agent installs without it. Each such reduction is a distinct `! reduced:` line in the plan, not a dim note, and a `reduced` list in `--json`, the assessment and the registry. Cases: Copilot CLI web search (Copilot CLI 1.0.105 grants none: a `web_search` entry grants nothing, and `github-mcp-server/web_search` asks GitHub's MCP server for a tool it does not offer), Gemini CLI delegation (subagents cannot invoke agents), Cursor read-only agents and their MCP tools, and delegation limited to some agents where a target cannot limit it.

**Losing shell needs an opt-in.** An agent that would lose the shell access it uses (Cursor's `readonly`, the only restriction Cursor has; scoped shell rules such as `Bash(git diff *)` on harnesses without scoped rules; `permissionMode: plan`) installs only with `agnthub add --allow-without-shell` (MCP: `allow_without_shell`). Without it the item is refused with that instruction; the registry lists such a harness as installable with the opt-in (`opt_in: allow-without-shell`) and the site's install command adds the flag.

**Stricter mappings.** `permissionMode: plan` converts as read-only: no edits, shell, delegation or MCP tools, each a reduction the agent used (Claude Code keeps it natively). Codex `sandbox_mode = "read-only"` withholds edits elsewhere; on Codex it stays refused, since Codex applies the parent session's sandbox; `workspace-write` and `danger-full-access` install on Codex with that note. Restriction-like fields a native Variant's own harness ignores (Cursor `tools`, Copilot `agents`/`allowed-tools`/`maxTurns`, Codex `features.multi_agent`, Claude Code `allowed-tools`) are honored where other harnesses can express them and install on their own harness as written, with a warning that the harness does not enforce them. Background agents run in the foreground with a note. Agent-scoped MCP servers install natively on Gemini CLI (`mcp_servers`) only. OpenCode's `permission.bash` patterns carry exactly between Claude Code scoped rules and OpenCode.

**Sources that convert as before keep winning.** When an agent has several sources, conversion takes the first that converts exactly under the earlier rules; only when none does, the first that needs one of these readings (a portable core with Claude Code fields, a field its own harness ignores, a lowered behavior, agent-scoped MCP servers), then the first with reduced capability, then the first without the shell. So no install changes source, or gains or loses capabilities, because another of the agent's files became convertible, and locks of earlier converter versions still restore.

**Still refused:** restrictions a target can only express in prose or by loosening: Codex agents that withhold edits, Cursor agents that withhold reads, hooks with real events, and agents whose instructions need `${CLAUDE_PLUGIN_ROOT}` (Claude Code users are pointed to installing the plugin itself). `isolation: worktree` was refused here too until [ADR 0014](0014-emulate-worktree-isolation-and-manual-only-invocation.md).

Consequences: a restriction still never becomes looser silently, and every change to what an agent can do is visible in the plan. Authors of portable cores written for another harness (OpenCode `mode`/`permission`, Gemini `kind`) get Claude Code's reading: restriction-like keys keep refusing, so nothing is loosened, but such an author should add a native Variant. The opt-in is per command and not recorded: `update` and `restore` need the flag again for such an agent.
