# Read `<id>.agent.md` portable cores as Copilot CLI agents

Status: accepted (2026-11-07). Amends [ADR 0012](0012-portable-cores-as-claude-and-reduced-capability.md) for portable cores in GitHub Copilot's file form.

ADR 0012 reads every portable core as a Claude Code agent. That is right for the `agents/*.md` files written for Claude Code, but `<id>.agent.md` is GitHub Copilot's own form: github/awesome-copilot keeps its 200 agents as `agents/*.agent.md`, and organization agents live in a configuration repository's root `agents/`. Their `tools` lists use Copilot's aliases and VS Code's tool names (`read`, `search`, `web/fetch`, `edit/editFiles`, `codebase`), which Claude Code matches case-sensitively and grants nothing for. So `tools: [read, search, web/fetch]` read as an allowlist that grants nothing: refused on Claude Code ("allows no tools"), Codex and Cursor ("it excludes read, search…"), and installed without any tool on OpenCode, Copilot CLI, Gemini CLI and omp. In awesome-copilot that hit all 144 agents with a `tools` list.

**A portable core named `<id>.agent.md` is read as a Copilot CLI agent.** Its frontmatter has the meaning a `.github/agents/` file has ([ADR 0009](0009-cross-harness-conversion-through-shared-semantics.md)):

- `tools` maps each entry to what Copilot CLI 1.0.105 grants for it, runtime-verified for every alias and every entry of awesome-copilot (harness-agent-formats.md, "Copilot CLI tool names"): the documented aliases, the VS Code names Copilot CLI accepts (`codebase`, `editFiles`, `runCommands`…), a namespaced entry by its last segment (`read/readFile` is `read`), and `web/fetch`. Entries Copilot CLI grants nothing for (`problems`, `fetch`, `WebSearch`, `read/problems`, `github/*`) are left out with a note each, which only withholds. An allowlist that grants nothing still grants nothing (only the `skill` tool Copilot CLI always offers), and a `tools` value agnthub cannot read refuses.
- `model` is Copilot's: kept on Copilot CLI, noted elsewhere. A VS Code model list is omitted with a note.
- `disable-model-invocation`/`infer`, `agents`, `allowed-tools`, `maxTurns`, `mcp-servers` and `skills` mean what they mean in a Copilot CLI agent; `handoffs` and `argument-hint` (IDE-only) are noted.
- Keys Copilot CLI ignores are omitted with a note, unless they read as a tool or permission restriction (`readonly`, `permission`, `disallowedTools`…) or as another dialect's delegation or restriction (`spawns`, `subagents`, `excludeTools`…), which refuse as in any portable core.

Copilot CLI agents read `.github/agents` files the same way, so the corrections apply there too: `WebSearch` grants nothing (it was read as web fetch) and namespaced entries grant their last segment's alias (they were read as MCP tools that grant nothing).

Consequences: awesome-copilot's agents with `tools` install everywhere Copilot CLI's grant can be expressed (144 of 200 were refused on Claude Code, Codex and Cursor; 56 remain refused on Codex or Cursor, which cannot withhold read or edits). Conversions of such files change, so this is converter `v7`: `check` shows changed files as a converter change and `update` rewrites them; `restore` of a `v6` lock reproduces every file `v7` renders unchanged and refuses, by digest, one it renders differently. A file named `<id>.md` keeps ADR 0012's Claude Code reading even when it uses Copilot names: its author's harness is not known. So does an `<id>.agent.md` file that declares a field only Claude Code defines (`permissionMode`, `disallowedTools`, `hooks`, `mcpServers`, `memory`…): some Claude Code collections name their agents so, and their fields keep the meaning they were written with.
