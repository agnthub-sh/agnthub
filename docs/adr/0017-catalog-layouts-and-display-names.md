# Discover catalog layouts and accept display names

Status: accepted (decided by the user on 2026-11-07). Amends [ADR 0002](0002-agent-variants-and-conservative-conversion.md) and [ADR 0012](0012-portable-cores-as-claude-and-reduced-capability.md) on agent identity.

Some of the largest agent collections keep their agents in top-level "division" folders instead of `agents/`: msitarzewski/agency-agents (about 280 agents) has `engineering/engineering-search-relevance-engineer.md`, `marketing/…`, `game-development/unity/…` beside `scripts/`, `integrations/`, `examples/` and `strategy/` documents. Each file is a Claude Code style agent whose `name` is a display name (`name: Search Relevance Engineer`) with cosmetic keys (`color`, `emoji`, `vibe`). Discovery found no agents there, and a display name refused an agent in every layout but Copilot CLI's and OpenCode's.

**Catalog layout.** Without `agnthub.yaml`, and only when every other layout (portable, native directories, plugins) yields no agent, discovery reads the repository's top-level folders as a catalog:

- **Candidates.** A Markdown file directly in a top-level folder, or one level down (`game-development/unity/unity-architect.md`), whose YAML frontmatter has a non-empty `name` and `description` and that has instructions after it. Hidden and `_` folders, folders for documentation, code, tooling, examples, templates, tests, translations, other harness content (`docs`, `scripts`, `examples`, `templates`, `tests`, `fixtures`, `node_modules`, `vendor`, `integrations`, `skills`, `commands`, `prompts`, …) and repository documents (`README.md`, `CONTRIBUTING.md`, `CHANGELOG.md`, `SKILL.md`, `AGENTS.md`, …) are never candidates.
- **Records of other products.** A catalog file has no structural signal, so its frontmatter must be an agent's: more than half of its keys are fields of some harness's agent format or common descriptive metadata (`color`, `emoji`, `vibe`, `tags`, …), and it has no `id` or `slug`. No harness format defines those two keys; a file that names itself with one is a record in another product's registry: IntentKit's `public_agents/` platform configs (`slug`, `visibility`, `search_internet`), Vibeyard's `personas/` team library (`id`, `role`), gbrain's `recipes/`. Such repositories are not catalogs, even when their files read like agents.
- **Divisions.** A folder is a division when at least two thirds of its Markdown files are candidates. Its first three files are read first; a folder they do not qualify is not read further, so a documentation-heavy repository costs at most three reads per folder.
- **Repository.** The repository is a catalog when its divisions with at least three agents hold at least five together; smaller divisions of the same repository then count too (agency-agents' one-agent `research/`). A docs folder with a couple of frontmatter pages, or a repository with two such files, offers nothing.
- **Why only without other agents.** A repository that publishes agents through a recognized layout has said where they are; its other Markdown is far more often documentation, and reading every top-level folder of every repository would multiply discovery's reads (and the registry's re-assessments, which replay only the files discovery read). Authors who want both can add `agnthub.yaml`.
- The planner fetches the tree listing, then the probe files, then the rest of the divisions, within the existing entry, file, byte and candidate budgets. `--list` shows each agent's division (`division engineering`, and `division` in `--list --json`).

**Identity.** An agent's identifier comes from its location, normalized: the file name without `.md` (or `.agent.md`, `.toml`) or the `agents/<dir>/` name, ASCII-folded (`Café` → `cafe`), lowercased, with every run of other characters one `-` (`Search Relevance Engineer.md` → `search-relevance-engineer`), underscores kept, at most 64 characters. Identifiers that were valid before are unchanged. Two files that normalize to one identifier are reported as ambiguous, never merged; a file name with no identifier characters left (`计划.md`) is a problem.

**Display names.** A declared `name` that is not an identifier (spaces, capitals, punctuation) is a display name, in every layout: it never decides the identity and never refuses an agent on its own. A root `AGENT.md` is named by its normalized name. An identifier-shaped `name` that disagrees with the location is still a mismatch, except in a catalog, whose file names are the identity. Native files identified by `name` (Claude Code, omp, Codex, Cursor, Gemini CLI, plugin agents) take the identifier from the file name when `name` is a display name.

**What each harness gets** ([research](../research/harness-agent-formats.md#agent-names-verified-2026-11-07)). Only Gemini CLI rejects a display name (`name` must match `^[a-z0-9-_]+$`; it has `display_name`). Claude Code (verified with 2.1.309), omp, Codex and Cursor load one, but `name` is what they invoke the agent by; Copilot CLI's identity is the file name and `name` is its label; OpenCode identifies by path and ignores `name`.

- **Authored files install byte-identical** into their own harness, display name included, wherever that harness loads it. A Gemini CLI variant with a display name stays invalid, as Gemini rejects it, and so does a Claude Code variant whose name Claude Code skips (a leading `-`, a `:`, more than 256 characters).
- **Generated files name the agent by its identifier** wherever the harness invokes agents by name (Claude Code, Codex, Cursor, Gemini CLI, omp): two collections' "Code Reviewer" would otherwise shadow each other, and delegation lists, conflicts, the lock and `remove` all use the identifier. Copilot CLI keeps the display name as its `name`, Gemini CLI as `display_name`; elsewhere it leads the description (`Search Relevance Engineer: Expert search engineer …`), which models read to pick an agent, unless the description already says it or it only spells the identifier. The plan notes it.
- **Same names are conflicts.** Since an authored file keeps its display name, two agents can carry one name in a directory. A harness that invokes agents by name would load only one, so the plan refuses the item as a conflict naming the other file (or the other planned agent), as for a path conflict.
- **Cosmetic keys** (`color`, `emoji`, `vibe` and other keys Claude Code ignores) are dropped from generated files with one note each, as ADR 0012 reads portable cores; they never refuse.

**Categories.** A division is a category hint, mapped to the taxonomy only where the mapping is obvious (`engineering` → `software-engineering`, `testing` → `testing-qa`, `security` → `security`, `marketing` → `marketing`, `game-development` → `game-development`, …; `specialized` maps to none). It is not a publisher category: the registry's categorization stays authoritative and uses the hint only where it has none of its own.

Consequences: catalog repositories are indexable and installable with no change by their authors. Agents refused only because of a display name or a file name with spaces become available, under the identifier their location implies. File names with spaces or unicode reach the lock as `sourcePath` and the registry's raw fetches escaped per segment; installed paths are always `<identifier>.<ext>`. A repository that gains an agent layout later stops being read as a catalog, which `update` reports as agents no longer installable. The registry must rescan, from GitHub, the repositories whose inventory this changes: re-assessment from stored files cannot add files discovery never read.
