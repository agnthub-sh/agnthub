## 1. Listing is not a prerequisite for installation

- **Documented:** skills.sh does not require a submission form or approval to enter its general leaderboard. Its FAQ says skills appear automatically from anonymous telemetry when users run `npx skills add <owner/repo>`; installations drive ranking. This is install-driven discovery, not a documented repository-registration workflow. The FAQ does not specify indexing latency, minimum counts, deduplication, abuse controls, or guaranteed eligibility. [FAQ](https://skills.sh/docs/faq)
- **Documented/source-observed:** the CLI accepts repositories, Git URLs, local directories, and direct downloads, discovers their contents, and installs them. A catalog listing is not an input requirement. `add <repo> --list` enumerates the source without installing; `find` searches the catalog. These are different operations. [CLI reference](https://github.com/vercel-labs/skills/blob/92a9a34ac3bf88e695e468b90c7bf32f163d32c8/docs/commands.md#skills-add), [resolution implementation](https://github.com/vercel-labs/skills/blob/92a9a34ac3bf88e695e468b90c7bf32f163d32c8/src/add.ts#L1194-L1279)
- **Documented:** a repository page lists skills the service has **seen**, not an asserted complete/current inventory of its Git tree. Public GitHub owners can customize presentation through a root/default-branch `skills.sh.json`; grouping configuration is refreshed in the background after telemetry-enabled installs, not page visits, and pages are cached. This is not ownership verification or publication approval. [Customization](https://skills.sh/docs/customize)
- **Design implication:** agnthub's requested repository registration should be an explicit product choice, independent of direct CLI installation. Do not accidentally make registry availability, telemetry consent, or an indexing queue mandatory for installing a known source.

## 2. Sources, providers, and refs

| Capability | Actual documented/source behavior |
| --- | --- |
| GitHub | `owner/repo`, `github:owner/repo`, full URLs, repository subpaths, and `owner/repo@skill-name`. **`@` selects a skill, not a version.** |
| GitLab | Full URLs, nested groups, `gitlab:` shorthand, and `/-/tree/<ref>/<subpath>` forms. Generic Git handles other hosts. |
| Azure Repos | Cloud/server `/_git/<repo>` URLs; `path` selects a subdirectory and `version=GB...` / `GT...` select branch/tag. The parser omits `GC` commit-version values. |
| Git refs | Git-like inputs accept `#ref` and `#ref@skill`; branch/tag refs are carried into lock entries. Git checkout first tries branch/tag cloning and supports a full 40-character commit SHA through a fetch fallback when the server permits it. Do not treat this as an npm-style semver resolver. |
| Private repositories | Existing Git credentials; GitHub HTTPS can fall back to authenticated `gh repo clone`, then SSH. Optional explicit `GITHUB_TOKEN` / `GH_TOKEN` support API operations. Private installation is distinct from public directory listing. |
| Local sources | Relative/absolute paths; no registry needed. |
| Website-hosted sources | Preferred `/.well-known/agent-skills/index.json`, legacy `/.well-known/skills/index.json`; current discovery supports `skill-md`/archive artifacts with digest and legacy per-file manifests. Scoped paths must not silently fall back to installing the entire host catalog when the requested scope cannot be resolved. |
| Direct downloads | A valid `SKILL.md` or ZIP/tar/tar.gz/tgz archive, even without an extension. Defaults: 10 MiB download, 25 MiB extracted, 1,000 files; configurable limits. Well-known discovery precedes generic download fallback. |

Sources: [command/source and authentication reference](https://github.com/vercel-labs/skills/blob/92a9a34ac3bf88e695e468b90c7bf32f163d32c8/docs/commands.md#source-formats), [source parser](https://github.com/vercel-labs/skills/blob/92a9a34ac3bf88e695e468b90c7bf32f163d32c8/src/source-parser.ts), [commit checkout](https://github.com/vercel-labs/skills/blob/92a9a34ac3bf88e695e468b90c7bf32f163d32c8/src/git.ts#L20-L79), [well-known provider](https://github.com/vercel-labs/skills/blob/92a9a34ac3bf88e695e468b90c7bf32f163d32c8/src/providers/wellknown.ts#L10-L138).

Selected GitHub owners/repositories have a blob-download fast path with Git-clone fallback; this is an optimization, not a registration prerequisite. ## 3. Multi-skill discovery and installation UX

- **Format:** each skill is a directory with `SKILL.md`, YAML `name` and `description`, plus optional supporting files. `metadata.internal: true` hides it unless `INSTALL_INTERNAL_SKILLS` enables it. [Authoring reference](https://github.com/vercel-labs/skills/blob/92a9a34ac3bf88e695e468b90c7bf32f163d32c8/docs/creating-skills.md)
- **Discovery:** root `SKILL.md`, standard `skills/` and harness-specific containers, special curated/experimental/system directories, Claude plugin manifests, and custom `skills.sh.json.paths`. Container walks are bounded to three levels; a shallower skill shadows descendants. Duplicate names keep the first discovered skill. With no standard-location results it recursively searches; `--full-depth` also discovers outside conventional containers. Manifest-declared paths are not subject to that depth-3 bound. [Discovery rules](https://github.com/vercel-labs/skills/blob/92a9a34ac3bf88e695e468b90c7bf32f163d32c8/docs/creating-skills.md#skill-discovery)
- **Selection:** interactive searchable multi-select, descriptions, plugin grouping, and select-all. A single skill is automatically selected. Repeated `--skill`/`-s` chooses named skills; `--skill '*'` chooses all skills while retaining explicit harness selection. `--all` means **all skills, all harnesses, and yes**, not just all repository entries. [Options](https://github.com/vercel-labs/skills/blob/92a9a34ac3bf88e695e468b90c7bf32f163d32c8/docs/commands.md#options), [selection source](https://github.com/vercel-labs/skills/blob/92a9a34ac3bf88e695e468b90c7bf32f163d32c8/src/add.ts#L1910-L2069)
- **Important automation default:** `-y` with no skill filter also selects every discovered skill. Running inside a recognized agent automatically enables noninteractive mode and selects that harness plus universal targets unless explicitly overridden. With `-y`, no recognized installed harness can mean targeting every harness. These are actual convenience defaults, not necessarily safe defaults to copy into an agent-definition installer. [Agent-context behavior](https://github.com/vercel-labs/skills/blob/92a9a34ac3bf88e695e468b90c7bf32f163d32c8/src/add.ts#L1766-L1785), [noninteractive targets](https://github.com/vercel-labs/skills/blob/92a9a34ac3bf88e695e468b90c7bf32f163d32c8/src/add.ts#L379-L391)
- **Placement:** project scope by default, global through `-g`; interactive scope/method prompts. Shared `.agents/skills/<name>` plus harness symlinks avoids duplication; copy mode creates independent copies. Actual paths vary, some harnesses have no global scope, and many now read the shared project directory directly. Single-directory installs default to copy. Installed-harness detection uses adapter-specific configuration/path checks; host-agent detection is a separate mechanism. [Harness paths](https://github.com/vercel-labs/skills/blob/92a9a34ac3bf88e695e468b90c7bf32f163d32c8/docs/agents.md), [adapter checks](https://github.com/vercel-labs/skills/blob/92a9a34ac3bf88e695e468b90c7bf32f163d32c8/src/agents.ts#L1-L110), [method default](https://github.com/vercel-labs/skills/blob/92a9a34ac3bf88e695e468b90c7bf32f163d32c8/src/add.ts#L399-L404)
- **omp backend caveat:** this pinned skills target table has no `omp` identifier. omp's own skill documentation lists `.agents/skills/` and `~/.agents/skills/` among default compatible locations, subject to discovery settings and higher-priority sources. Therefore an agnthub omp adapter can investigate supported shared-destination installation, but must not assume `skills --agent omp` exists or that a file on disk is necessarily active. This path compatibility is documentation evidence, not a runtime-verified adapter. [skills target table](https://github.com/vercel-labs/skills/blob/92a9a34ac3bf88e695e468b90c7bf32f163d32c8/docs/agents.md), [omp skills and compatible locations](https://omp.sh/docs/skills#compatible-locations)

## 4. Lifecycle and lock files

- `list`/`ls` enumerates installed project skills; `-g` selects global and `-a` filters harnesses. `check` does not reinstall and exits 1 when updates exist. `update [names...]` supports project/global selection and noninteractive scope detection. `remove` supports named skills, exact lock source, scope, harness filters, interactive selection, and all; its `--all` is all skills/all harnesses/no confirmation. [Command reference](https://github.com/vercel-labs/skills/blob/92a9a34ac3bf88e695e468b90c7bf32f163d32c8/docs/commands.md)
- **Project:** version-1 `skills-lock.json`, intended for Git; sorted names, no timestamps. Entries hold source/type, optional original URL/ref/path, content SHA-256 over the skill directory, and optional installation mode/package metadata. Keys are skill names, not source-qualified identities. **Global:** version-3 `~/.agents/.skill-lock.json`, or `$XDG_STATE_HOME/skills/.skill-lock.json`; records original URL/ref/path, folder hash, timestamps, and remembered prompt/target selections. These schemas serve provenance/update tracking, not a universal immutable package store. [Project schema](https://github.com/vercel-labs/skills/blob/92a9a34ac3bf88e695e468b90c7bf32f163d32c8/src/local-lock.ts#L5-L76), [global schema](https://github.com/vercel-labs/skills/blob/92a9a34ac3bf88e695e468b90c7bf32f163d32c8/src/skill-lock.ts#L6-L77)
- `experimental_install` restores supported project-lock sources into `.agents/skills/`, not harness-specific links; already-present skills are skipped unless `--force`. In frozen mode restored content must match recorded hashes; differing sources are skipped, lock unchanged, exit 1. Frozen mode defaults in CI. `experimental_sync` handles installed npm packages and package-declared remote skills; these are explicitly experimental features. Do not describe all restoration as complete immutable revision replay. [Restore/sync contract](https://github.com/vercel-labs/skills/blob/92a9a34ac3bf88e695e468b90c7bf32f163d32c8/docs/commands.md#experimental-commands)
- Update support is source-dependent: project remote-update collection skips local and `node_modules` sources. agnthub should define its own update matrix rather than promise uniform updates for every accepted source. [Update collection](https://github.com/vercel-labs/skills/blob/92a9a34ac3bf88e695e468b90c7bf32f163d32c8/src/update.ts#L324-L343)
- **Additional specification check:** the Agent Skills specification defines `metadata` as arbitrary string key/value pairs and shows `metadata.version: "1.0"` as an example; it does not define mandatory semantic versions, comparison rules, or a version resolver. A strict semantic-version policy is therefore an agnthub convention, not existing universal skill behavior. [Agent Skills specification](https://agentskills.io/specification#metadata-field)

## 5. Telemetry, ranking, and trust

- **Website claim:** rankings use aggregate anonymous install telemetry; homepage offers All Time, Trending (24h), and Hot. The API describes Hot as comparison of the last hour with the same hour yesterday. Counts measure installs, not task success, unique satisfied users, compatibility, or safety. No inspected source establishes an anti-gaming or uniqueness guarantee. [FAQ](https://skills.sh/docs/faq), [homepage](https://skills.sh/), [API view definitions](https://skills.sh/docs/api)
- **Source is more specific than website copy:** telemetry schemas include install/remove/update/find/sync events, source and skill identifiers, target harnesses, global scope, skill-file paths, optional install URL/caller metadata, CLI version, CI flag, and detected host harness; `find` includes query/result count. The website's “only aggregate installation counts” language is therefore not a full description of the current CLI payload. No conclusion about server retention or identification is supported by this client inspection. [Telemetry source](https://github.com/vercel-labs/skills/blob/92a9a34ac3bf88e695e468b90c7bf32f163d32c8/src/telemetry.ts)
- GitHub source/skill identifiers and audit requests require positive public-repository confirmation; unknown/private GitHub visibility is skipped. Other remote types can still send identifiers because visibility cannot be checked through GitHub. Either nonempty `DISABLE_TELEMETRY` or `DO_NOT_TRACK` disables telemetry **and security-audit requests**. [Configuration/privacy caveat](https://github.com/vercel-labs/skills/blob/92a9a34ac3bf88e695e468b90c7bf32f163d32c8/docs/troubleshooting.md#telemetry), [public audit gate](https://github.com/vercel-labs/skills/blob/92a9a34ac3bf88e695e468b90c7bf32f163d32c8/src/add.ts#L2070-L2082)
- Security pages combine Gen Agent Trust Hub, Socket, and Snyk; results can differ and can be pending. CLI audit lookup times out/fails open rather than preventing installation. The CLI warns that skills run with full agent permissions; the website explicitly cannot guarantee every listed skill's security/quality and recommends review. **Listing, popularity, first-party origin, a verified GitHub organization, and an audit result are distinct signals.** [Audits](https://skills.sh/audits), [nonblocking audit implementation](https://github.com/vercel-labs/skills/blob/92a9a34ac3bf88e695e468b90c7bf32f163d32c8/src/telemetry.ts#L95-L131), [CLI warning](https://github.com/vercel-labs/skills/blob/92a9a34ac3bf88e695e468b90c7bf32f163d32c8/src/add.ts#L2728-L2732), [security disclaimer](https://skills.sh/docs)
- Filesystem/download safeguards exist (sanitized names/subpaths, containment checks, archive/download limits); these do not sandbox the installed instructions or guarantee their behavior. [Installer checks](https://github.com/vercel-labs/skills/blob/92a9a34ac3bf88e695e468b90c7bf32f163d32c8/src/installer.ts#L60-L94), [download limits](https://github.com/vercel-labs/skills/blob/92a9a34ac3bf88e695e468b90c7bf32f163d32c8/docs/commands.md#examples)

## 6. Website product surfaces worth separating

Observed/documented surfaces: searchable ranking views with activity/install counts; harness directory pages; repository collection pages with grouped entries and repository-wide install commands; skill detail with install command, summary, rendered `SKILL.md`, related/topic skills, source link, stars, first-seen date, activity, and per-provider audits; topic browse; official first-party curation; audit directory; badges; documentation/API; and packs. [Homepage](https://skills.sh/), [repository example](https://skills.sh/vercel-labs/agent-skills), [detail example](https://skills.sh/vercel-labs/agent-skills/web-design-guidelines), [official/API definition](https://skills.sh/docs/api), [badge docs](https://skills.sh/docs)

Packs are an additional sharing product, not repository indexing: Vercel sign-in to create/manage; public catalog entries plus uploaded/private GitHub-derived content; multiple valid skills per folder/archive/repository; URL installation without authentication. **Unlisted is not private/access-controlled:** anyone with the URL can view/install. Deletion disables the link. [Packs contract](https://skills.sh/docs/packs)

## 7. What agnthub cannot simply copy

The following are **design implications**, not claims that skills already solves agent installation:

1. **Harness support is artifact-specific.** Skills' compatibility rests on `SKILL.md` and a shared Agent Skills specification; its own compatibility table still varies for hooks, tools, and fork context. A supported *skill target* is not evidence that the same harness supports installable *agent definitions*. [Compatibility caveats](https://github.com/vercel-labs/skills/blob/92a9a34ac3bf88e695e468b90c7bf32f163d32c8/docs/agents.md#compatibility)
2. **One logical agent can have variants.** Define logical identity, source revision, variant selection, target-native filename/schema, and whether conversion is lossless. Skills' name-keyed locks/first-name-wins discovery are not sufficient evidence for a multi-variant agent model; TOML conversion must not silently drop tools, permissions, model settings, or semantics.
3. **Destination management may not be directory copying.** Native agent configuration may require configuration-file registration/merging, different scope/precedence, and artifact-specific uninstall ownership. Skills' `.agents/skills` canonical directory and broad symlink approach are not a verified shared agent location.
4. **All needs a precise boundary.** Distinguish all logical agents in a source, all variants, and all compatible installed harnesses. Avoid inheriting `--all = all harnesses` or agent-context `yes = every discovered item` without an intentional decision.
5. **Updates need generated-artifact provenance.** Record source/ref/content hash plus selected variant, converter/schema version where relevant, installed destinations, and ownership so removal cannot delete user-managed agent configurations. Decide how local edits and agent name collisions behave.
6. **Trust/privacy need independent contracts.** A registry entry should show compatibility validation separately from security findings and popularity. Define repository ownership/registration policy, public/private boundaries, telemetry opt-out, indexing refresh, and whether safety lookups are independent of analytics consent.

Unresolved product decisions for the design session: public registration mechanism and refresh trigger; initial Git hosts/ref grammar; stable agent identity and collisions; variant precedence versus conversion; supported native artifact matrix; project/global defaults; exact meaning of all; immutable pinning versus moving-ref updates/local edits; telemetry/ranking policy; audit policy; and private-source support versus public indexing. OpenAgent support remains a separate later capability, not inferred from any skills CLI target.
